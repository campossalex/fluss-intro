Shipment Lookup

GET /shipments/<id> · fluss.app.shipment_status

Where is a shipment right now? Each lookup is a point read by primary key on the Fluss PK table shipment_status — no Flink job in the path. The shipment-status job (Lab 2, Step 5) keeps the table up to date as scans arrive.

Latency test

Looks up one shipment over and over for a fixed time and reports the latency percentiles. Measured inside the API service around each Fluss lookup, so the browser and HTTP are not in the numbers. The test keeps running if you close this pop-up.

Concurrency is the number of lookups kept in flight, each through its own Fluss lookup client. Try 1, then 8 or 32: throughput grows with it while each lookup's latency stays about the same.
